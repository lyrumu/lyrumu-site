# Notes to Hugo

把用户指定的 Notes 笔记整理为适合本站阅读的 Hugo 文章；也可只更新已有文章或补卡片图。

## 优先级与边界

- **内容保真**：保留原文的措辞、观点、信息、例子、命令、提示词、叙述顺序、第一人称和个人语气。可把句子移入合适的标题、列表、表格、步骤或图注，但不改变原意、不遗漏信息，也不为“完整”而补写观点、教程、步骤、风险段落、开场或总结。只有明确错字、误粘贴重复、转换歧义、难懂指代、必要前提或来源归属等具体问题才作最小修正；拿不准就保留并指出，影响使用时先问。非排版改动在交付时说明理由。
- **源文件与范围**：项目根目录为 `/Users/lyrumu/project/lyrumu-s-page/knowledge-base`；`/Users/lyrumu/project/Notes` 全目录只读，包括原稿、附件和 `.obsidian`。只写目标文章包 `content/notes/<name>/`、对应卡片图 `assets/image/notes/` 和 `data/notes.yaml` 中该文章的映射；保护现有 WIP，不改无关文章、布局、样式或数据项。文章内容和单篇配图不写入 `DONE.md`；`DONE_ARCHIVE.md` 只读。
- **配图顺序**：先保持本站整体风格，再让图案体现该文独有的主题与内容，默认不用文字。差异来自主体、视角和元素关系，不靠换整套画风，也不照搬相邻卡片。
- **发布边界**：不 `git add`、commit、push、部署或自行启动 Hugo server。

## 按任务读取与创建

- **完整迁移**：先查 `git status --short` 与目标 diff，完整读原稿、`archetypes/notes.md`、`content/notes/_index.md`，浏览现有文章的 front matter 和标题结构，再完整读 2–4 篇主题、篇幅或类型相近的文章。archetype 是新文章字段、顺序和默认值的唯一模板；从旧文学习排版与 taxonomy，不把其额外字段反写进模板，也不照搬措辞。未点名源文件、匹配多个文件或无法确认已有目标目录是同一篇文章时，先问。
- **已有文章正文更新**：沿用完整迁移的读取范围，另读完整目标与相关 diff，合并站点侧人工改动，不整篇覆盖。**仅补图**时只读目标文章及下述卡片链路，不执行整篇迁移检查。

## 网站化编排

完整理解原稿后按内容关系选择标题、段落、表格、列表、步骤、代码、提示词块、引用与图注；不能只转换 Wiki 语法，也不能为制造差异改写原意。

- 正文不重复页面标题；主要章节用 `##`，并列方法/阶段用 `###`，确有下一级才用 `####`。目录应概括全文，不堆“关键要素”“步骤”等空泛碎标题。至少两个稳定字段的短信息优先用表格，长段落和图片不塞表格；有先后关系用有序列表，否则用无序列表，不用散落段落模拟步骤或给无序项强加序号。
- 终端命令用带语言标记的围栏代码块，可复制的自然语言 prompt 用 `text` 围栏；行内代码只放简短术语、按键和参数，不用斜体引用或行内代码承载长 prompt。版本范围、必要前提、注意或推荐紧邻相关内容用引用块，普通正文不滥用引用。
- 图片放在对应说明或步骤之后，写准确 alt；需辨认阶段/差异时加 Markdown 图片标题，连续图片逐张说明。每段表达一个要点，避免整句加粗；正文仅在主要章节转换时用独立一行 `***`，`---` 留给 front matter。
- 配置/命令笔记按任务设 `##`，执行/恢复等真实阶段用 `###`；前提紧邻命令，命令可独立复制，恢复方法不埋在段尾。课程/方法长文按课程章节和并列方法分层，表格、步骤、`text` 提示词、过程截图图注各归其位，不堆同级碎片。
- 若成稿除 front matter、链接和空行外几乎未变，视为迁移未完成，应复查是否遗漏有价值的层级、块类型、可复制性、图注和阅读节奏；不为通过检查而扩写原意之外的内容。

## 整理规则

### 目标与 front matter

- 用户指定目录名就照做；否则用源文件名去 `.md`，仅把连续空格改为 `-`，保留 Unicode，不擅改 URL。新文章用 `hugo new content "notes/<name>/index.md" --kind notes` 创建，不用 `--force`。
- 新文章 `date` 为整理当天；更新文章保留原日期，有实质更新才启用 `showDateUpdated` 并填写当天日期。`slug` 留空、`weight: 0`，除非用户明确要求置顶。
- `title` 和 `description` 取自真实内容；摘要用正文主要语言写得具体。tags/categories 少而准确，优先复用现有词；只有确属新文章类型才新增，不确定就保留空数组并询问。

### 正文与读者视角

- 将 Obsidian Wiki 链接、嵌入、callout、脚注等改为本站可渲染的 Markdown；不能发布的内部链接改为自然文本，若影响理解先问。只在脱离 Obsidian 后确实难懂或易误用时补最少的指代、前提或来源；不虚构经历、数据、结论，也不抹平有意强调或简洁语气。
- 通读标题、摘要、开场、正文、图片说明和结尾：面向首次到访读者，不写“原笔记记下了”“按你的要求”等交付口吻，不把助手的整理行为写成作者经历，也不机械地把真实的“我”改成“你”。助手为向作者交代而加的编辑待办或未验证说明放在交付回复，不写进正文或另建文章日志。
- 保留必要署名、版本范围、来源链接占位和真实的不确定性；不擅删原稿的“未验证”或尚未核实的模型名，也不用面向作者的免责声明替代事实。疑点在交付时指出。

### 网页剪藏或 AI 原始材料

- 根据正文、front matter、来源链接和用户提示判断材料属性；转载属性不明先问，不把第三方内容冒充用户原创。网页剪藏可去导航、广告、推荐阅读、重复页脚等噪音，不删作者正文。确因版权需摘要/改写时只做必要部分并说明，不套用于用户自己的笔记。
- 保留原始来源、署名，短引文注明来源并区分原作者观点。命令、安全建议、价格、版本和平台规则等易变事实：用户要求更新或核实时查当前一手资料；否则保留原稿时间语境，无法确认的标明或在发布前询问。

### 图片与附件

- 只复制正文引用的本地附件：先解析相对路径及 Notes `assets/`，再放到目标包 `image/`；原件不动。将 `![[assets/example.png]]` 改成带准确 alt 的相对 Markdown 链接；文件名冲突时用稳定可读的新名并同步链接。不复制未引用附件或 `.obsidian`。
- 远程图片不自动下载；若它是必要内容且用户未说明保留、替换或删除，先询问。

### 文章卡片配图（默认必做）

- 新迁移文章默认生成主题相关卡片图；既有文章保留合适旧图，缺图或用户要求更换时才生成，用户明确不要则不做。先读 `layouts/partials/article-link/card.html`、`assets/css/_13_notes-card.css`、`data/notes.yaml` 并查看 2–3 张近期配图，辨认共同风格与重复构图。
- 共同风格为暖米白纸纹、浅浮雕/剪纸拼贴、低饱和炭灰/灰蓝/橄榄色、少量陶土色和柔和阴影。以无需文字也能辨认的主题主体为中心，用少量次要图案体现内容；产品标志须准确且有依据，不伪造标志或界面，不把笔记本、盆栽、泛化图标组当通用封面，也不直接复用课程截图。默认无文字、字母、数字或伪代码；确需文字时先由用户决定。
- 用 `imagegen` 技能和内置工具逐篇生成约 16:9 横图；主体放中央安全区，上方元信息和底部标题留白，考虑 `object-fit: cover`。实际查看并缩到卡片尺寸检查风格、主题、裁切与相邻卡片差异，不合格重做。
- 最终图放 `assets/image/notes/<name>.<ext>`；按 `.File.ContentBaseName` 在 `data/notes.yaml` 添加/更新唯一映射，`image` 写 `image/notes/<name>.<ext>`，沿用 Hugo WebP 缩放和模糊占位，不为卡片额外开启正文 hero。保护旧图与映射；更换时用新文件名，除非用户明确要求删除旧图。工具不可用时完成其他整理，报告配图未完成，不用图标/占位冒充。

## 完成检查

1. 完整迁移时比较源 Markdown 和引用附件前后的 SHA-256；逐段核对成稿是否漏写或擅改，复查层级、表格/列表、步骤、命令/提示词、图注、强调、分隔符和读者视角。检查无残留 `![[...]]`、`file://`、本机绝对路径、抓取噪音或失效内链。仅补图时只检查图片与映射。
2. 检查卡片图落盘、映射唯一且路径可解析，仍走缩放与占位管线；运行 `git diff --check`。若失败来自已有 WIP，说明归属，不顺手修改。
3. 运行一次非服务构建：`hugo --renderToMemory --themesDir themes --theme blowfish --config hugo.toml --cacheDir /tmp/lyrumu-hugo-cache`。若用户已有本地预览，可复用它检查桌面和窄屏的标题、表格、代码、图注及连续图片节奏；不自行开长期服务。无预览时只称构建通过，浏览器视觉验收待用户完成。
4. 交付时简报目标文件、复制附件、卡片图与风格、必要的非排版改动及理由、源文件未变证明、验证结果和待用户决定事项；明确未做 Git 发布。
